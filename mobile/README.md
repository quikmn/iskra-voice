# Iskra for phones (Capacitor)

One app shell for phones: [Capacitor](https://capacitorjs.com) 8.5.2 around the built web client (`client/dist`), which is
bundled into the app rather than loaded from app.iskra.foo. The app opens without the network, reads as a real app for
App Review (guideline 4.2), and updates its web part with each app release.

- **iOS / iPadOS** (`mobile/ios/`): iPhone and iPad, iOS 16+. Bundle id `foo.iskra.app`, team `BWX2M8XSNZ`, name "Iskra".
  Built and uploaded to TestFlight by `.github/workflows/mobile-ios.yml` on GitHub's macOS runners. Nobody needs a Mac.
- **Android** still ships as the Trusted Web Activity in `android/` until phase 2 (below).

| Path | What it is |
|---|---|
| `package.json`, `package-lock.json` | Capacitor CLI, the iOS platform and the plugins, all pinned exactly |
| `capacitor.config.ts` | App id, name, `webDir: ../client/dist`, colours, keyboard and status bar settings |
| `ios/App/App.xcodeproj` | The Xcode project (generated by `npx cap add ios`, then edited: team, entitlements, iOS 16) |
| `ios/App/App/Info.plist` | Display name, permission texts, `iskra://` scheme, ATS, export compliance |
| `ios/App/App/App.entitlements` | Associated Domains: `applinks:app.iskra.foo` (links) and `webcredentials:app.iskra.foo` (app lock passkeys) |
| `ios/App/App/Assets.xcassets` | App icon (one 1024 px image) and launch image, made by `scripts/icons.py` |
| `ios/App/CapApp-SPM/Package.swift` | Swift packages for Capacitor and the plugins (rewritten by `cap sync`) |
| `scripts/icons.py` | Icon and launch image from the bolt in `desktop/assets/icon.png` (`python mobile/scripts/icons.py`, needs Pillow) |
| `../scripts/mobile-version.mjs` | Version and build numbers (tested with the release scripts: `npm test` at the repo root) |
| `../client/src/platform/native.ts` | The client's side: detects the app, opens links, saves files, sets the status bar |

The Xcode project is committed; `ios/App/App/public` (the copied web app), `capacitor.config.json`, `config.xml` and
`capacitor-cordova-ios-plugins` are generated by `npx cap sync ios` and ignored. Swift packages (no CocoaPods) resolve
on the build machine, so `cap add`/`cap sync` work on Windows too; only building needs macOS.

## Build

CI does everything (see [docs/ci-cd.md](../docs/ci-cd.md#ios-app) and the playbook's task "build iOS and upload to TestFlight"):

```
gh workflow run mobile-ios.yml                      # build main, upload to TestFlight
gh workflow run mobile-ios.yml -f ref=v2.0.0-alpha.10
gh workflow run mobile-ios.yml -f upload=false      # build, sign and check only; the .ipa is a run artifact
```

Steps: newest released Xcode on `macos-latest` → `client` `npm ci && npm run build` → `mobile` `npm ci && npx cap sync ios`
→ `xcodebuild archive` → `xcodebuild -exportArchive` with cloud signing → checks (bundle id, versions, encryption key,
Associated Domains entitlement, signature) → a second export with `destination: upload` sends it to App Store Connect.

Signing is automatic with the App Store Connect API key; there are no certificates or profiles in the repo or in
GitHub. The archive is signed ad hoc (`CODE_SIGN_IDENTITY=-`, so CI never creates development certificates), then the
export signs it with Apple's cloud-managed distribution certificate. If Xcode refuses that, run the workflow with
`-f archive_signing=automatic` (normal automatic signing: Xcode makes an "Apple Development: Created via API"
certificate on each fresh runner; revoke old ones in Certificates if the portal complains).

On a Mac, by hand: `cd client && npm run build`, `cd mobile && npm ci && npx cap sync ios && npx cap open ios`.

### Versions

- `CFBundleShortVersionString` = the numeric part of `desktop/package.json`'s version (`2.0.0-alpha.10` → `2.0.0`).
- `CFBundleVersion` = `<code>.<run>.<attempt>`: Android's version code (`2.0.0-alpha.10` → `20000110`, alpha 1xx,
  beta 2xx, rc 3xx, final 900), then the workflow's run number and attempt. Every release, and every rebuild of one,
  gets a higher build number, which App Store Connect requires.
- Both are passed to `xcodebuild` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`); the project's own `1.0`/`1` are placeholders.

## How the web client runs inside the app

The page is served from `capacitor://localhost` by the app itself. What depends on the page's origin:

| Thing | In the app |
|---|---|
| Iskra servers (WebSocket, uploads, files) | No origin checks on the server; HTTP endpoints answer `Access-Control-Allow-Origin: *`. Nothing to allow |
| Profile pages (framed) | The server's `frame-ancestors` lists `capacitor://localhost` (ProfilePages.cs, tested) |
| CSP (`client/src/csp.ts`) | Unchanged: `'self'` is `capacitor://localhost`; Capacitor's bridge script is injected by the web view |
| LAN servers without HTTPS | Work, like the desktop app: the page isn't `https:`, and ATS allows local networking. Public hosts need HTTPS (they have it) |
| Invite and message links the app shares | Point at the server's web app or https://app.iskra.foo, never `capacitor://` |
| Invite links tapped elsewhere | Universal Links (`https://app.iskra.foo/#/join/…`, `#/link/…`) and `iskra://join/…` open the app (`@capacitor/app`) |
| Microphone, camera | Info.plist texts; iOS asks once. Capacitor grants the web view's own media prompt, so there are no repeated prompts. Inline playback and autoplay are on |
| Screen sharing | Not possible in an iOS web view: the button is hidden (`canShareScreen`) |
| Downloads | Server files open in Safari (it saves them). Files made in the page (decrypted DM files, themes, calendar files) go to the share sheet ("Save to Files") through `@capacitor/filesystem` + `@capacitor/share` |
| Safe areas, keyboard | `viewport-fit=cover` and `env(safe-area-inset-*)` as in Safari; the web view resizes above the keyboard (`Keyboard.resize: native`) |
| Status bar | Light text on dark themes, dark on light themes (follows `data-scheme`); launch screen and web view background `#0B0B14` |
| "Add to Home Screen" hints, web push | Hidden in the app; Settings → Notifications says push comes in an update |
| Watch parties (YouTube) | As in the desktop app (no `origin` parameter on non-http pages). Check on a device |

## Universal Links

`client/public/.well-known/apple-app-site-association` is served at https://app.iskra.foo/.well-known/apple-app-site-association
(`_headers` gives it `application/json`). It lists `BWX2M8XSNZ.foo.iskra.app` for `#/join/*` and `#/link/*` only, so other
app.iskra.foo pages still open in the browser. iOS fetches it through Apple's CDN when the app is installed, so the web app
must be deployed with it (deploy.yml `webapp`) before testers install. iskra.foo itself has no invite links, so it needs no file.
Check: `curl -sI https://app.iskra.foo/.well-known/apple-app-site-association` (200, `application/json`, no redirect) and
`curl -s https://app-site-association.cdn-apple.com/a/v1/app.iskra.foo`.

## Owner setup (once, in the browser)

1. **Identifier.** developer.apple.com → Account → Certificates, Identifiers & Profiles → Identifiers → **+** → App IDs →
   App → Continue. Description `Iskra`, Bundle ID **Explicit** `foo.iskra.app`. Under Capabilities tick
   **Associated Domains** and **Push Notifications** (push is for phase 2; ticking it now avoids a profile change later).
   Continue → Register. (If `foo.iskra.app` is already registered, open it and tick the two capabilities → Save.)
2. **App record.** appstoreconnect.apple.com → Apps → **+** → New App. Platforms **iOS**; Name **Iskra** (if taken:
   "Iskra Chat", then "Iskra – Voice & Chat"; the name on the Home Screen stays "Iskra" either way); Primary Language
   English (U.S.) or English (U.K.); Bundle ID `foo.iskra.app` from the list (it appears a few minutes after step 1);
   SKU `iskra-ios`; User Access Full Access → Create.
3. **API key role.** App Store Connect → Users and Access → Integrations → App Store Connect API → Team Keys. Cloud
   signing for distribution needs an **Admin** key (App Manager isn't enough for cloud-managed distribution certificates;
   the current notarization key was made with the Developer role). If the key behind `APPSTORE_KEY_ID` isn't Admin:
   **Generate API Key** → name `iskra-github-ci`, Access **Admin** → download the .p8 (once), then from the folder with it:
   `base64 -w0 AuthKey_XXXX.p8 | gh secret set APPSTORE_API_KEY_BASE64`, `gh secret set APPSTORE_KEY_ID` (the new key id),
   `gh secret set APPSTORE_ISSUER_ID` (same issuer). macOS notarization in release.yml keeps working with it. Revoke the old
   key after the next release built fine.
4. **Agreements.** App Store Connect → Business: the Free Apps agreement must be active (accept any pending terms on
   developer.apple.com too); uploads fail while an agreement is waiting.
5. **TestFlight group.** App Store Connect → Apps → Iskra → TestFlight → Internal Testing **+** → name `Friends & family`
   (internal = people in the team, up to 100, no review), tick **Enable automatic distribution** → add testers (they must be
   users under Users and Access; add friends there with the role "Customer Support" or "Developer" if they aren't). For
   people outside the team: External Testing **+** → group → add the build → Beta App Review (about a day for the first build).
6. Testers install **TestFlight** from the App Store and accept the email invite.

### Export compliance

`ITSAppUsesNonExemptEncryption` is `false`, so builds don't stop for the encryption questions. Iskra uses only standard,
published algorithms (libsodium: X25519, Ed25519, XChaCha20-Poly1305, BLAKE2b; TLS and WebRTC's DTLS-SRTP from WebKit),
nothing proprietary, in a mass-market consumer app; that falls under the exemptions for mass-market encryption in
Category 5, Part 2 of the U.S. EAR (License Exception ENC §740.17(b)(1), classified 5D992.c), which App Store Connect
treats as "exempt" (no documentation upload). Other end-to-end messaging apps make the same declaration (Signal-iOS and
Element X both ship `ITSAppUsesNonExemptEncryption = false`).
**For the owner to confirm (not legal advice):** whether the U.S. annual self-classification report applies (since 2021
most mass-market (b)(1) items don't need one), and **France**: supplying end-to-end encryption in France may need a
declaration to ANSSI. If unsure, leave France out of the App Store availability for the public release (TestFlight
isn't a store listing) or file the declaration. Change the key and answer the questions in App Store Connect if the answer changes.

## Known gaps (phase 2)

- **Push notifications.** Web push doesn't reach an app's web view. Plan: APNs through a small Iskra push relay (servers
  are self-hosted and can't hold Apple's key; the relay holds the APNs key and forwards sealed wake-ups the server can't
  read), registered with the existing push protocol; needs the `aps-environment` entitlement and the Push capability (step 1).
- **Calls in the background.** iOS suspends the web view when the app leaves the screen, so voice stops. Needs the
  `audio` background mode plus CallKit (and PushKit for incoming calls) in native code.
- **Screen sharing** (ReplayKit broadcast extension) and **picture in picture** for video.
- **Swift package versions.** Capacitor's packages are pinned, but `ion-ios-filesystem` (from `@capacitor/filesystem`) resolves
  "from 1.1.1" on each build; commit `Package.resolved` once a Mac or CI run produces one.
- Swedish permission texts (an `sv.lproj/InfoPlist.strings`); the app already declares English and Swedish.

## Phase 2: Android joins

Android moves from the Trusted Web Activity (`android/`) to this same shell, so phones share native push and background voice:

1. `npm install --save-exact @capacitor/android@<same as @capacitor/ios>` here, `npx cap add android` (→ `mobile/android/`),
   add `android: { path: 'android' }` to `capacitor.config.ts`, and `cap sync android` in a CI job like the iOS one.
2. **Keep the package id `foo.iskra.app` and the same signing key** (`devkeys\iskra-android.keystore`, alias `iskra`) so
   installed APKs update in place. Version codes keep the scheme in `scripts/mobile-version.mjs` (versionCode() already
   matches `android/build.ps1`); the new app's first code must be higher than the last TWA build.
3. `client/public/.well-known/assetlinks.json` stays (App Links for `#/join/` invites; add Play's app-signing fingerprint if Play signs).
   Add an intent filter for `https://app.iskra.foo` with `autoVerify` and the `iskra` scheme.
4. Then remove `android/` (Bubblewrap, `build.ps1`) and the TWA-specific bits: the `android-app://` referrer check in
   `client/src/ui/installHintKind.ts` (the native check covers it) and the APK step in `scripts/release-windows.ps1`.
5. Things that differ from iOS: the page origin would be `https://localhost` (Capacitor's Android default) — keep the
   `blockedAsInsecure` exception working (set `server.androidScheme: 'http'` or extend the check), add that origin to the
   server's `frame-ancestors`, and `RECORD_AUDIO`/`CAMERA` permissions in the manifest.
